# Pre-release review (November 2026)

A review of everything that changed since the version the group used (`ebb0ff4`): the toolchain migration,
the data layer and the new Google Drive sync, the rules engine, and the UI. Ticked items are fixed.

## Verified unchanged

- Rules engine: 2,548 generated characters (every class × school × race, levels 1–10, both rule variants,
  equipment, conditions, companions, GM adjustments) derive identically in the old and the new engine; only
  reworded diagnostic messages differ. Same result under each repo's own test runner (Jest vs Vitest).
- All 74 rules-data and model modules export identical content.
- A character exported from the old app imports and derives identically.
- React 19 + Chakra 2 + framer-motion 14: ~780 buttons clicked on desktop and mobile, no errors. Sub-path
  hosting, offline use and the update flow work.
- No secrets, private emails or rulebook text anywhere in the history; 0 known vulnerabilities in runtime
  dependencies.

- [x] 2. One edit starts a full sync every ~2 s for as long as the token is valid (unstable hook dependencies).
- [x] 3. Edits made during a sync round can win without a conflict copy; clock skew between devices can revert
      a newer version everywhere.
- [x] 4. Two near-simultaneous uploads can lose one write (Drive's check-then-write isn't atomic).
- [x] 5. Restoring a backup on a new device and then enabling sync (or turning sync off and on) overwrites

- [x] 6. Safeguards: reject a sync file from a newer app version; one sync file even if two devices create one;

## Notes on the fixes

- Sync (1–6) was redesigned rather than patched: one file per device (only that device writes it), version
  vectors instead of clock comparisons, deterministic conflict copies, strict reads, a roster store outside
  React. Covered by `src/state/driveSync.test.ts` (scenarios + randomized multi-device runs; each of eight
  deliberately planted merge bugs makes it fail) and by two browser runs against a fake Google and Drive.
- 7: build target ES2018 / Safari 12 / iOS 12 (verified by parsing the bundle); the desktop zoom is set from
  script because the CSS pipeline rewrites media queries into range syntax regardless of the target.
- 8: every record from a file, Drive or storage is normalised and trial-derived (`normalizeRecord`); the roster
  cards survive a record the engine can't derive; an app-level error screen offers reload and "save all".

- Ψ/⅓: Crimson Pro has neither glyph at all, so a ~1.7 KB EB Garamond subset (OFL) supplies just those
  four characters through `unicode-range`, scaled to Crimson Pro's capital height.
- TypeScript now checks the app against the ES2019 library, so using an API newer than the iOS 12 floor
  fails the typecheck; the Vite config has its own `tsconfig.node.json`.

## Second review: an independent adversarial pass over the rebuilt sync

- [x] A character the rules engine can't compute (a future engine bug) was dropped on load and from Drive:
      now only repaired, never rejected; per-screen error view with export; unreadable data offered on the roster.
- [x] An old deletion marker from the first sync build deleted a live character on first load.
- [x] Storage full: a sync round reloaded the older saved state over the unsaved edit.
- [x] The sheet's draft editors (equipment, companions, conditions) overwrote another device's change.
- [x] Two tabs: a stale tab reused a version number and wiped the other tab's edits.
- [x] Two devices with the same id (restored browser data) dropped each other's edits.
- [x] A device with a clock far ahead froze daily backups; an edit followed by a delete before syncing wasn't backed up.
- [x] Merge order could keep an older version as a spurious copy.
- [x] Smaller: unreadable downloads cached; odd ids breaking backup names; the first sync build's shared file
      never read; backup names duplicated across time zones; backed-up list kept across accounts.
